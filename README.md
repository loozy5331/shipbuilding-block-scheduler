# 조선소 블록 일정 스케줄러

조립 공정 생산관리자가 블록 정보와 가용 자원을 입력하면

1. **현재 가용 자원으로 전 블록 납기 준수가 가능한지** 판정하고, 불가능하면 원인과 *어떤 자원을 몇 개 늘리면 해소되는지* 제안하고
2. **가용 자원 안에서 최적의 블록·작업자·크레인·비상 자재 배치**를 계산해 간트 차트로 보여 줍니다.

배치는 드래그 & 드롭으로 직접 고칠 수 있고, 고칠 때마다 일별 자원 부하와 납기를 즉시 다시 검증합니다.
서버 없이 브라우저에서만 동작하며 입력·배치는 브라우저(localStorage)에 저장됩니다.

## 실행

```bash
npm install
npm run dev       # 개발 서버
npm run build     # 정적 빌드 (dist/)
npm test          # 단위 테스트 (Vitest)
npm run e2e       # E2E 테스트 (Playwright, headless)
```

## 사용법

0. **진입** — `숙련자` / `신입` 모드를 고르면 2×2 메뉴(엑셀 업로드 · 튜토리얼 · 설정 · 블록 작업 촬영(준비 중))가 나옵니다. 숙련자는 `최적 배치` 버튼, 신입은 최적 배치와 비교해 한 가지씩 알려 주는 `힌트` 버튼을 씁니다.
1. **입력** — 엑셀 업로드(끌어 놓기) / 엑셀 셀 복사-붙여넣기 / 직접 입력. `엑셀 양식` 버튼으로 템플릿을 받을 수 있습니다.
   - 필수 열: `블록 ID`, `납기일`, `필요 작업 시간`, `자재준비 여부` (열 순서 무관, `남은 기간`·`필요 공수(MH)` 같은 별칭 인식)
   - 납기일이 날짜면 계획 시작일 기준 "남은 일수(오늘=1)"로 환산, 숫자면 그대로 사용
   - 자재: `준비/미준비`, `완료/미완료`, `Y/N`, `O/X`, `TRUE/FALSE`
   - 자원: 작업장 수, 동시 처리 블록 수, 일반 작업자(하루 8MH), 숙련공(하루 12MH), 크레인, 비상 자재
2. **배치** — 화면에 들어오면 현재 자원으로 전 블록 납기 준수가 가능한지 바로 판정합니다. 간트의 한 줄은 작업장(작업 자리) 하나이며, 굵은 선이 작업장 경계입니다. 상단 아이콘(작업자·숙련공·크레인·비상 자재)을 대기 블록이나 막대에 끌어 놓아 배정하고, 막대를 좌우로 끌면 착수일, 위아래로 끌면 작업장이 바뀝니다(같은 작업장에서 날짜가 겹치면 `작업장 겹침`).
3. **TBM** — 간트 날짜를 누르면 그날 작업장별 블록·인원·주의 사항이 TBM 메시지로 정리되어 복사/공유할 수 있습니다.
4. **평가서** — 최적 배치 대비 납기 만족 블록 수(클수록 좋음), 잔여 납기 여유일(클수록 좋음) 등을 비교합니다.
5. `엑셀 내보내기`로 배치표(작업장·작업자 수 포함)·일별 자원 부하·요약·TBM·평가서 시트를 받습니다.

예시 엑셀: `public/sample-tutorial.xlsx`(발표 자료의 5블록), `public/sample-30-blocks.xlsx`.
처음 모드를 고르면 튜토리얼(발표 자료 "작업 배정 실습 10일 아침의 다섯 블록")이 자동으로 열리며, 상단 `튜토리얼` 버튼으로 다시 볼 수 있습니다.

## 배치 규칙

- 블록의 하루 처리량 = 일반 작업자 수 × 8MH + 숙련공 수 × 12MH, 작업 기간 = ⌈필요 MH ÷ 하루 처리량⌉일 (연속 작업)
- 작업 중인 날마다: 동시 작업 블록 ≤ 작업장 × 동시 처리 수, 투입 인원 ≤ 보유 인원, 블록마다 크레인 1대
- 자재 미준비 블록은 비상 자재 1개를 써야 착수 가능 (비상 자재는 소모성)
- 블록당 최대 투입 인원은 `세부 설정`에서 조정 (기본 3명)

## 최적화 방식 (`src/solver/`)

목적함수(사전식): 미배치 블록 수 → 자원 초과 → 납기 지연 블록 수 → 총 지연일 → 비상 자재 사용 → 낭비 MH → 전체 완료일

1. 블록별 인원 구성 후보 생성, 지배되는 구성 제거 (`modes.ts`)
2. 납기별 누적 필요 MH vs 가용 MH 용량 사전 검사 (`feasibility.ts`)
3. 블록 순서를 받아 각 블록을 가장 좋은 시작일·인원 구성에 놓는 직렬 스케줄 생성 (`sgs.ts`)
4. 납기 빠른 순(EDD)·여유시간 순 초기해에서 교환·삽입 로컬 서치 + 재시작 (`search.ts`, Web Worker에서 약 0.8초)
5. 불가 판정 시 자원별로 +1~+3 추가해 재계산하는 What-if 제안 (`whatif.ts`)

## 구조

```
src/domain/     타입, 배치 평가(evaluate: 부하·지연·초과 판정 — UI/솔버/테스트 공용)
src/solver/     최적화 엔진, Web Worker
src/io/         엑셀/붙여넣기 파싱, 내보내기
src/store/      Zustand 상태 (localStorage 저장)
src/components/ 입력 화면, 배치 화면(간트·자원 부하·정책 비교·What-if), 아이콘
src/tutorial/   튜토리얼 시나리오와 단계
```
